# Test Design Skill
## Activation
Use when a requirement, story, acceptance criteria, or endpoint description needs test coverage.
## Inputs
Requirement text, constraints, field definitions, or endpoint contract.
## Procedure
1. Extract actors, preconditions, outcomes, inputs, and constraints.
2. Apply at least two techniques: equivalence partitioning, boundary value analysis, decision table, pairwise, or state transition.
3. Include positive, negative, and boundary scenarios where relevant.
4. Prioritize scenarios and map each to an expected result.
## Output
Requirement summary; technique(s); assumptions; test cases with ID, title, preconditions, steps/input, expected result, priority; coverage gaps.
